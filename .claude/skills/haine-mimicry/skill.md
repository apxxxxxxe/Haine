# haine-mimicry: 手本駆動の新規ランダムトーク作成

## 設計思想（作業前に必ず読む）

`haine-batch-write` の反省から生まれた。**規則を足しても WithYou の品質は上がらなかった**——規則の山（アンチパターン A〜K、観点 1〜15、A-1〜A-6 細則）は writer をチェックリスト充足に最適化させ、防御的で痩せたトークを生んだ。本スキルは **足し算をやめ、引き算する**。核は5つ：

1. **手本駆動が骨格**：題材に構造の型が最も近い**既存トーク1本**を深く写す。「規則で禁じる」のでなく「実例で示す」
2. **1題材＝1手本**：複数を混ぜると平均化して痩せる。1本だけを濃く写す
3. **単一セッション生成**：手本の質感を要約で劣化させないよう、手本原文を保持したまま書く
4. **批評だけ独立サブエージェント**（`haine-talk-check`）：自己レビューの甘さを新鮮な目で補う
5. **北極星制約（禁止と狙いの二極）**：禁止は一つ——ハイネは立場差を利用してユーザに優位に立つな。狙いも一つ——対等な二者の摩擦を書く。**優位を消すことと、ハイネを無害化することは別物**（詳細は「北極星制約」節）

## 引数の解釈

- **category**（必須）: `WithYou` / `Lore` / `Past` / `Abstract` / `AboutMe` / `Servant`
  - ※ 全カテゴリ手本プール整備済み（WithYou は「北極星」軸、他カテゴリは構造マップ軸。各カテゴリの表を参照）
- **topic / direction**（任意）: 題材または方向性
- **count**（任意、デフォルト 1〜3）: 生成本数

category が無ければユーザに尋ねる。

## 実行フロー（単一セッション）

### ステップ 0: 基礎情報の確認

2つの参照元を Read する。

**(a) 表現の基礎**：本スキル同梱の `references/expression-basics.md`（性格・口調・表現パターン）と、`.claude/dev/talk_format.md`（表示速度とウェイト仕様・全体長の目安・書式とマークアップ）。

**(b) 世界観設定**：`.claude/lore/haine_about.md`。全カテゴリ共通で「登場人物」のハイネ節は必ず読み、加えて**カテゴリ別の重点節**を読む：

| category | haine_about.md の重点節 | 追加資料 |
|---|---|---|
| **WithYou** | 「登場人物」ユーザ節／「二人の関係性」／「世界観」ハイネの館 | 所作の舞台の詳細は `.claude/lore/mansion_layout.md` |
| **AboutMe** | ハイネ節（生活実態・現代技術との距離）／「世界観」ハイネの館 | `.claude/lore/mansion_layout.md` |
| **Lore** | 「霊体社会」／「世界観」カンテルベリオ | |
| **Servant** | 「霊体社会」（契約・従者たち） | |
| **Past** | ハイネ節（生前・自殺の経緯） | |
| **Abstract** | （世界観依存が薄い。ハイネ節のみで足りることが多い） | |

迷ったら多めに読む。題材が複数節にまたがるなら該当節をすべて読む。

※ 旧 `talk-guide` スキルは 2026-07-02 に廃止済み。その規則群（アンチパターン群・観点群・A-1〜A-6 細則）は参照も復活もさせない（引き算対象）。

### ステップ 1: 題材確定＋既存トークの確認

`randomtalk.rs` を Grep し、当該カテゴリで同じ題材を扱う既存トークを把握する。**題材レベルの被りは許容する**——面白い題材は数が限られており、被りを理由に周縁の題材へ逃げると面白くならない（つまらない題材を選ぶ→却下→未反映なので次回また同じ題材を選ぶ、のループの原因になった）。弾くのは**実質的な同一トーク**だけ：既存トークと場面・展開・着地まで重なる焼き直し。同じ題材で書くときは、被る既存トークを読んだ上で別の場面か別の角度を取る。direction があれば沿わせる。

題材に迷ったら `.claude/lore/haine_derived.md` 1章（台詞に反復する傾向とトークの種）と `.claude/lore/situations.md`（場面別の一問一答）を種として引いてよい。**ただし用途は題材探しまで**——人物のトレイト記述を出発点に台詞へ直訳すると、本人に性格を自己解説させるトークに流れる（haine_derived.md「生成トークのクセ検出」）。situations.md の 150〜299 は現代パロ想定なので、場面ごと種にはできない（判断の型のみ）。

### ステップ 2: 型マッチング＋手本1本選定

題材がどの型に属するかを判定し、その型の手本候補から**最も構造が近い1本**を選ぶ（「WithYou 手本プール」／「他カテゴリの手本プール」参照）。**型を勾配リスクで避けない**——リスクは「手当てが要る場所」であって「角を丸めて逃げる場所」ではない（→「北極星制約」節）。型6 該当時は型6注釈に従う。

### ステップ 3: 手本の精読（省略禁止）

選んだ手本1本を `randomtalk.rs` から**全文 Read** し、以下を掴む：

- 場面の組み立て（誰の動作が起点か、ユーザの反応がどう参加するか）。**`\1`（scope1）は必ずユーザ視点の一人称**——思考・観察・セリフであり、三人称ナレーター（地の文）は存在しない。ハイネの所作を `\1` で書けるのは「ユーザが見ている」から。ゆえに**ユーザ自身を三人称で描く（「ユーザは〜」）／意識のないユーザ（眠り等）を起点にする**のは不可——語り手が消える。ハイネのセリフは `\0`・hコード
- 1行の折りリズム、`[half]` の置き方、表情コードの呼吸
- **着地の質**（手本がどう「漏らす／決める」か）

### ステップ 4: 草稿生成（手本を深く写す）

手本の**構造・呼吸を写し、題材だけ差し替える**。手本の型を保ち、感情は手本と同じ置き方で置く。書き終えたら**北極星を両極で自問**する：(1) 優位を笠に着ていないか【禁止】(2) 観察眼・ユーザの輪郭・危うい芯が削れて無害化していないか【狙い】。どちらかで怪しければ書き直す（型6 は型6注釈を厳格適用）。

### ステップ 4.5: AI slop 自己点検（stop-ai-slop-talk-jp）

草稿を `stop-ai-slop-talk-jp` で自己点検する。まず `references/examples.md`（既存トークの実物を劣化させた AI版/人間版 対比6例）を読み、次に同スキルのクイックチェックを上から通す。

**修正の優先順位はスキル側に従う**——(1) 感情の名指し (2) 内面の代弁 (3) 着地（前振り・詩的総括）(4) 声の混同 (5) 語彙と記号。1と2を直さずに語彙だけ直しても台詞は人のものにならない。

鉄則は「削る・具体に落とす」。情緒を *説明する* 動きは、現在の即物的な行動・観察に落とす——情緒は置くもの、説明するものではない。

※ 資料・ドキュメントの日本語（`.claude/` 配下）は従来どおり `stop-ai-slop-jp` が担当。トーク本文には talk 版を使う。

### ステップ 5: 批評（サブエージェント `haine-talk-check`）

`Agent` tool で `haine-talk-check` を起動。プロンプトに含める：

```
- category / topic / 草稿（Rust コードブロック）/ 使った手本ID
3点のみ検証（北極星 / 手本照合 / 世界観矛盾）。観点1〜15・A-1〜A-6は使わない。
```

🔴 があれば草稿を直して再度かける（最大2ラウンド）。

### ステップ 6: 提示

「草稿 + 使った手本ID + 属する型 + reviewer の3点結果」を提示する。**採否の最終判定はユーザの読み味**。machine の合格を最終としない。

## WithYou 手本プール（型分類）

軸＝**ハイネの立ち位置／権力勾配の向き**。題材をこの7型のどれかに当てはめ、最も近い1本を写す。

| 型 | 構造 | ハイネの立ち位置 | 勾配リスク | 手本候補（ID） |
|---|------|----------------|:---:|---------|
| **1. 観察され、素が漏れる** | ユーザがハイネを観察→ハイネが自覚し無防備に | 見られる側（勾配が反転） | 低 | `食事中の読書` / `くしゃみ` / `携帯電話を使わない` |
| **2. 所作の変化→応酬** | ハイネの所作・変化にユーザが気づき往復になる | 対等 | 低〜中 | `取れたボタン` / `袖のほつれ` / `菓子の切り分け` |
| **3. ユーザが先、ハイネが追う** | ユーザの持ち物・才能にハイネが関心→自分も開く | 追う側 | 低 | `あなたのゴスファッション` / `スケッチ` / `リップクリーム` |
| **4. 失敗・矛盾→自嘲** | ハイネが失敗し自嘲する | 下に出る | 低 | `舌やけど` / `振り子時計の調整` / `食べ物の好き嫌い` |
| **5. 死者性が所作に滲む** | 死者性・世界観が行動に現れる（説明でなく） | 異なる存在 | 中（説明に傾くと「死者の優位」が出る） | `蝋燭の交換` / `霧の力` / `写真には写らない` |
| **6. 気遣う／関係を言葉にする** | ハイネからユーザへ気遣い・見透かしを向ける | 上から | **高** | `時間の流れ方` / `生前の食事事情` |
| **7. ユーザの質を拾って肯定する** | ユーザの癖・質にハイネが心を動かされ、それを肯定する。判定・値踏みでなく、動かされた側として | 動かされる側／下に出る | **高** | `生きた字` / `匂い` |

### ⚠️ 型6 の慎重注釈

型6 は権力勾配リスク最大。気遣いは必ず**撤回・自嘲・委ね・両義性**で包み、ハイネが**采点・値踏みして完結させない**（既存例「あなたは数えてる？ ……ならば、それで充分だわ」）。**ただし型6を避けて安全な型へ逃げない**——リスクが高い型ほど手当てして書く。逃げると無害で空虚なトークになる（リスク列は「避ける場所」でなく「手当ての必要度」と読む）。

### ⚠️ 型7 の慎重注釈

型7 も勾配リスク最大。肯定が**采点・値踏み**（外部の物差しで測り、判定で締める）に転ぶと却下。受動を担保する二点で書く——①ハイネが**動かされた徴**を出す（審査員は動かされない。動かされている時点で受動）②「良い／悪い」でなく「これはこういうものだ」という**事実の言明**として置く。ハイネ固有の読み替え（死・霊・100年の読書を通す）が采点と肯定を分ける関門で、これを飛ばすと采点（「いい字だね」）に落ちる。**型6同様、リスクを理由に安全な型へ逃げない**。手本は `生きた字`。

## 北極星制約（二つの極）

WithYou の合否を分ける本質。**禁止は一つ、狙いも一つ。この二つを混同しないことが最重要**。禁止だけを見ると「無害であれ」と取り違え、温かいが空虚なトークになる（観察が丸まり、ユーザが書割化し、ハイネの芯が薄まる）。

### 禁止 ── 消すのは「優位」だけ

> **ハイネは立場差を利用して、ユーザに優位に立っていないか？**

ハイネ（ホスト）とユーザ（ゲスト）には権力勾配がある——ゲストはホストを求めるが、ホストにゲストを求める必然性はない。この非対称でハイネが上→下の優位を笠に着ると却下される。「対等な友人なら微笑ましい」発言も、立場差ゆえに別ニュアンスが乗る。（本節が現在このプロジェクトのパワーバランス方針の唯一の生きた記述。`CLAUDE.md`「パワーバランス設計」節から参照されている）

- ❌ 見下し・からかいの権力性で着地する（「私のひとり勝ちよ」型）
- ❌ ハイネが**采点・値踏み**して完結する（外部の物差しで測り、判定で締める。「よくできました」式）
- ❌ ハイネがユーザを**試す・値踏みする・仕掛ける**（依存するゲストを操る＝勾配の裏口侵入）
- ✅ ハイネが見られる／追う／下に出る／無防備になる
- ✅ 気遣いを撤回・自嘲・委ね・両義性で包む
- ✅ **感嘆・畏敬をもってユーザの質を肯定する**（型7）。采点との違いは「ハイネが動かされているか（受動）」——打たれて漏れる肯定は許可、測って下す判定は禁止。**この二つの混同が最も危険**：采点を嫌うあまり肯定まで避けると、型7ごと無害化して空虚になる

### 狙い ── 対等＝二つの鋭さの摩擦

**優位を消すこととハイネを無害化することは別物**。消すのは「優位」だけ。次の**3つの歯は優位と無関係なので、むしろ強く残す**：

1. **観察眼の容赦なさ**：観察は具体的で、時に気まずいほど鋭くユーザを射抜く。温かく丸めない
2. **ユーザの輪郭・押し返し**：ユーザを書割にしない。筆談・絵・ゴス・自殺願望・沈黙という武器を持ち、ハイネに押し返す。二者の張りを作る
3. **ハイネの危うい芯**：死者性・厭世・偏り・壊れた感性。当たり障りのない癒し役に薄めない

対等とは柔らかさではなく、二つの鋭さがぶつかること。

### ⚠️ 危うさの向き（edge と勾配の再絡まりを防ぐ）

「危うい芯」は**ハイネ自身が露わになる**向きで出す（観察が自分に跳ね返る／危うさが自分の壊れを晒す／押し返しがちゃんと刺さる ＝ ○）。同じ危うさを**ユーザを試す・測る・仕掛ける**向きに使うと、edge の顔をして勾配が裏口から戻る（×）。危うさはハイネを**無防備にする**方へ向け、**優位にする**方へは向けない。

## 禁忌

- 足し算に戻る（規則の山を参照・適用して writer を縛る）
- 複数手本の平均化（1題材1手本を破る）
- 手本を読まずに書く（ステップ3省略）
- machine の合格を最終とする（採否はユーザ）
- stop-ai-slop-talk-jp 点検（ステップ4.5）を省略する
- ユーザの指示なくトークを randomtalk.rs にコミットする
